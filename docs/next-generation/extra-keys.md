# Extra-key editor model (in progress)

`ExtraKeyLayout` is an in-memory model for the existing `extra-keys` array. It accepts representative upstream JSON-like single-quoted and unquoted syntax, checks one to three rows with up to 24 keys per row, and preserves complete key objects—including unknown fields, macros, display names and nested popup objects—when moving them. It rejects duplicate object fields, malformed keys and oversized or overly complex input. It exports valid JSON accepted in principle by the existing extra-key format; exact Android parser compatibility still requires device or Android framework tests. Layouts outside these limits are rejected for editing and must not be silently replaced.

The model provides Classic, Coding, Vim, Tmux and Compact starting layouts, plus row/key add, remove and move operations. A user-edited configuration can serve as a custom layout. Settings now offers a native editor with a visual row preview, tap-based movement, add/remove operations, presets, revert and explicit save. Advanced key and popup objects can be edited as JSON; macros and popups are labeled. Saving chooses the current first-readable properties path, validates with the existing Android extra-key parser, uses the append-only backup layer, and asks the terminal activity to reload the keybar when it resumes without restarting sessions. Drag-and-drop, a dedicated graphical macro/popup editor, named profiles, per-session overrides and full profile import/export are still missing. Those are required before this workstream is complete.

`./gradlew :app:testDebugUnitTest --tests com.termux.app.extrakeys.ExtraKeyLayoutTest` tests representative parsing, presets, field preservation, defensive copying and bounds. It does not exercise the Android view or actual properties files.

The save path opens the final file with `O_NOFOLLOW`, rejects non-regular, differently owned or hard-linked files, never truncates the original, and reports a changed snapshot as a conflict. It writes a private backup before appending. Invalid UTF-8, malformed properties, oversized input and a final unfinished continuation are rejected. A partial write, sync failure or changed path after writing is reported as an uncertain outcome with the backup path so a caller can inspect before retrying. Failed backups may leave an incomplete backup file.

The checks cannot atomically exclude a shell process that modifies the file between the final comparison and append; external writers do not necessarily honor advisory locks. A caller must recheck primary/secondary properties-file precedence, explain this limitation, and perform all file I/O off the UI thread. Ancestor directory symlinks and Android platform behavior require further review. The Android instrumentation tests cover backups, conflicts, new-file permissions and final-component links but have not been run on a device.

The editor rechecks properties-file precedence and rejects redirected configuration directories before reading and saving. The checks cannot prevent a same-UID process from replacing an ancestor between validation and open. The editor stores its bounded unsaved preview and an identity fingerprint in Android saved state. After recreation it reloads the properties and permits Save only when the original file identity and contents still match; a save in flight also blocks saving after recreation. Export the preview and reopen after inspecting a conflict. Android may not restore saved state in every process termination or user dismissal, and an in-flight import or export can be interrupted. A failed or uncertain save must be inspected before retrying; no device tests or UI screenshots are available yet.

The editor can import or export a single layout through the Android system document picker without requesting broad storage permissions. The UTF-8 JSON document has the form `{"version":1,"rows":[...]}` using the existing key objects; it is not a multi-profile backup. Imports are capped at 256 KiB plus 64 bytes, reject unknown versions and fields, and are validated before replacing the unsaved preview. The user must choose Save separately to update properties. Exports use the selected document provider and can leave an incomplete document if writing fails. Provider behavior, activity recreation during transfer and the picker flows have not yet been tested on a device.

Document picker results received while the editor reloads are queued until loading finishes. Lifecycle restoration, in-flight transfers, and URI grants require Android device testing; the fingerprint instrumentation test is compiled but has not been run on a device.
