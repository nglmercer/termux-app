# Termux process snapshot (in progress)

The terminal context menu has an opt-in, read-only **Termux processes** view. It takes active session and background task PID hints from the existing service and scans `/proc` on a worker thread. It includes visible processes with the app's real UID that are linked by parent PID to a visible session or task root. Background tasks whose PID is unavailable are counted separately. The view lists PID, parent PID, kernel command name, state and RSS in KiB. Search filters visible entries by name, PID or parent PID; sorting by PID, name, CPU or RSS is applied before the 100-row display limit. Unknown metrics sort after known values. Snapshot processing and sorting happen on the worker, and search operates on the bounded snapshot. Subsequent refreshes estimate CPU use as a percentage of one core from the difference in process CPU ticks; the value can exceed 100% for multithreaded processes. Matching PID and start ticks are required, and unavailable or decreasing counters are shown as unknown. CPU intervals use the times at which scans finish, so results are approximate, especially for slow scans. It does not read command-line arguments or environment variables. The scan visits at most 4096 numeric process directories, limits individual files, and displays at most 100 entries; inaccessible entries, missing roots and truncation are reported. Opening the dialog enables refreshes at least two seconds apart, with no overlapping scans. The dialog provides Pause, Resume and manual Refresh; closing it or stopping the activity cancels future refreshes. An in-flight scan may finish after dismissal but its result is discarded.

Each refresh requests Android's device memory, battery percentage, and thermal status on the worker thread. Device RAM is labeled as total minus available memory and is not a sum of process RSS; Android may account for reclaimable memory differently. Unsupported or inaccessible values are shown as unavailable. Thermal status requires Android 10 or later. These Android API calls have not yet been validated on a device.

This is a best-effort snapshot, not proof of current ownership: processes can exit, reparent or reuse PIDs while it is being gathered. Android may hide processes or restrict procfs. RSS counts shared pages and is not a measure of device-wide used RAM. There are no process signals or remote process APIs in this implementation. Configurable intervals, charts, process categories, PID-reuse-safe actions and Android device testing remain outstanding. Auto-refresh lifecycle and battery impact have not been measured on a device. Task PIDs depend on the existing AppShell PID lookup and may be unavailable on some Android versions; neither that lookup nor task lifecycle races have been validated on a device.

Search, sorting, accessibility and display behavior have not been tested on an Android device. Filtering does not expand Android process visibility or authorize process control.
