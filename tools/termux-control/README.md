# termux-control prototype

A small native client for the opt-in local control socket. It is not included in the APK, bootstrap or a released Termux package yet. The listener is disabled by default; the terminal context menu's Local control action offers read-only or read/write access until the service stops. All processes running under the app UID share the selected access. The Android socket and menu still need device testing. The client can send a bounded binary frame to a specific session but cannot attach to or stream terminal output yet.

Build locally with `make -C tools/termux-control` using a native Android/Termux C toolchain. The default socket path is `$HOME/../control-ipc/control.sock`; use `--socket PATH` or `TERMUX_CONTROL_SOCKET` if the home directory is nonstandard. Commands are `capabilities`, `list`, `create COLS ROWS [NAME]`, `rename ID NAME`, `resize ID COLS ROWS`, `close ID`, and `write ID` (reads 1–65536 bytes from stdin). `write` sends the supplied bytes exactly and does not add Enter; bytes supplied by the caller may themselves contain command-executing control characters. Results are JSON; errors go to stderr and return a nonzero exit status. The client checks that the socket peer has the same UID. A timeout after a request is sent may mean its outcome is unknown; inspect session state before retrying a mutating request.

For release, this source must be packaged and reviewed in the appropriate `termux-tools` or `termux-packages` repository for each supported ABI, with tests and an upgrade path. Building or copying this prototype locally does not establish a packaging or release strategy. No Python or Java runtime is needed by the client; `test-client.py` and `test-java-interop.py` are host-only tests; the latter checks the native client against the Java protocol loop, not Android LocalSocket.
